# 故障排查

[English](en/troubleshooting.md) · [首页](../README.md)

## 5555 连接被拒绝

“ADB 设置开启”不代表 adbd 在运行。先确认 IP 与网络，再在 Termux 运行 `/system/bin/setprop ctl.start adbd`。本机用该服务名成功；不要写 `adbb`。不要为此启动 ATCMD 服务或工厂菜单。

这条命令若被拒，说明环境与本机不同，停止；本文没有适用于所有长虹固件的通用提权方法。

## `unauthorized` 或认证失败

只有设备状态为 `device` 才能继续。若有调试授权弹窗，核对连接来源后由用户允许。本次早期认证失败后曾自动变成 device，原因未完整确认；不能当作认证绕过步骤。持续失败就停止。

## shell 连续输出 `Password:`

中止该客户端命令。必须先 `adb root`，重新连接后再执行 `id`。`tvctl.py` 对持续输出和时间做了限制，不会猜密码或修改系统密码。

## 安装失败或签名冲突

以实际 `Success` 判断安装成功，而不是只看进程返回码。确认 Android SDK、APK 来源与包名；旧安装签名不一致时不要自动卸载，因为会丢失应用数据。guard 和 standard 共用包名，也不能当作两个相互独立的应用随意覆盖。

## Aerial 前台正常，打开应用后 HOME 回长虹

先检查原厂“后台启动”，再查 PID/守护绑定。无障碍设置中有条目，并不证明进程还活着。本机缺少后台许可时，切后台约 1–2 秒就被结束。

真正的验收是：另一个应用保持前台，Aerial 在后台存活，再按实体 HOME。只在 Aerial 内按 HOME 或只执行 `am start` 都不够。

如果后台许可已开启、进程仍在而 HOME 失败，记录当时的 `Home Guard` 诊断行及原有服务，逐项排查。不要随意关闭长虹 TaskMonitorService、语音服务或所有无障碍。

## `filterHomeAlways`、自定义键码是否需要

本次不需要。Android 8 的守护已请求按键过滤；该配置主要针对其他系统行为，可能带来长按音量的副作用。固件有自定义 HOME 处理不代表必须修改系统键码。用户允许后台后报告 HOME 正常，应先保留成功配置。

## 已授权，但守护没绑定

先确认 `WRITE_SECURE_SETTINGS: granted=true`，检查是否仍禁用了整个 Aerial。可停止并重新打开 Aerial；本次只是将旧任务拉前台时没有触发完整初始化，重新启动应用后绑定成功。不要反复清空/覆盖无障碍全表。

## SSH 消失

Termux 也可能被厂商清理，或在重启后未启动。可打开 Termux，重跑自己的 SSH 初始化脚本；复查用户名、端口和主机指纹。不要为保住 SSH 把所有应用设为后台允许，也不要把普通 SSH 误认为 root。

Aerial 案例只批准 Aerial 的后台权限，Termux 没有因此被自动放行。若要长期允许 Termux 后台，需另行说明影响并授权。

## 升级后又失效

这版固件的安装处理包含将第三方应用加入后台清理名单的逻辑，覆盖安装也有相同路径。升级后重新确认：

1. 原厂 Aerial 后台启动状态。
2. WSS 权限、HomeGuard 的实际绑定状态。
3. 自身 BootReceiver 是否被限制。
4. 跨应用实体 HOME、声音、待机和用户关心的功能。

不要每次升级都先重置全部权限；先读取现状。需重启验证时先确认并准备恢复通道。

## 哪些日志不宜公开

只读取已知的设置键。不要执行 `settings list secure` 再把整份输出贴到 GitHub；本机历史配置中可能有网络凭据。原始截图、设备清单、完整应用日志、SSH known_hosts 和密钥都应留在本地，仅公开脱敏后的必要片段。

## 商店已安装，却打不开或不能安装别的应用

安装黑名单、运行黑名单和安装来源白名单是三个独立检查。先读取当前三份名单及开关，确认目标商店的实际包名；再核查它安装的目标 APK 是否被限制。只改其中一项可能不够，ADB 安装也不保证绕过框架检查。见 [安装策略维护](app-install-policy.md)。

## 名单写入后未生效，或者过一阵又失效

先复查文件字节、权限和系统实际规则，区分“文件未正确写入”“框架尚未重载”“官方刷新覆盖”。每次只读取相关键与必要日志。官方更新可重写名单，不应盲目反复恢复旧文件，更不能自行停用整个权限服务。

## 只有 SSH，但 pm 提示 app_process 找不到

这是 Termux 命令环境与 Android 系统工具的差异。可仅对该次命令设置 `PATH=/system/bin:/system/xbin:$PATH` 并取消 `LD_PRELOAD`、`LD_LIBRARY_PATH` 后再调用系统工具。这不授予 root；`dumpsys` 仍可能因缺少 DUMP 权限被拒。不要为了读不到一个诊断项就自动升级权限。

## 工具提示对照

`tvctl.py` 与 SSH 脚本目前主要输出中文，未实现语言切换。常见提示如下；完整失败原因仍以实际输出为准。

| 输出片段 | 含义与下一步 |
| --- | --- |
| `仅预览，未连接电视` | 没有执行设备操作；只有已有授权时才加 `--execute` |
| `root 身份和固件范围已确认` | 当前连接身份与完整 build 已通过检查；不代表开机自动恢复 |
| `操作未全部完成` / `命令超时或输出过多` | 操作停止，可能已部分执行；保留日志、读取现状，不盲目重跑 |
| `超出本指南实测固件范围` | 当前固件不匹配；停止修改，不删除校验 |
| `未确认 SSH 已启动` | 检查本脚本日志和 8022 端口占用，不结束未知 SSH 服务 |
| `主机公钥指纹` | 首次连接前与电脑提示逐项核对，不关闭主机校验 |
